## Что сделать

### 1. Пройти чек-лист в `npm run dev` (mock-режим)

- [ ] Меню → остановка 1 → все main-слова → авто-переход на завершение → 3★ → «Удвоить» (mock, ~0.5с) → «Дальше» → остановка 2;
- [ ] остановка 2: дубль (`СОК` ×2) — «Уже найдено»; чужие буквы (`ЗОНТ`) — тряска; короткое (`ТО`) — «Мало букв»;
- [ ] остановка 3: `ОМЕЛА` → чип «Бонус», очки ×2; все main без ОМЕЛЫ → 1★; отдельная сессия: все main + ОМЕЛА → 3★;
- [ ] клавиатура и тап дают одинаковый результат; Ё с клавиатуры = Е;
- [ ] перезагрузка страницы — игра стартует с меню (прогресс в памяти, сохранений нет — это норма недели 2);
- [ ] в mock-логах `[SDK:mock] gameplayStart/Stop` при входе/выходе из остановки.

### 2. Сборка артефактов

`npm run lint:dict` → `npm run lint && npm run typecheck && npm run build` → `bash scripts/package.sh` → полученный zip передать соло-разработчику для перезаливки в черновик (консоль Яндекса).

- [ ] gameplayStart/Stop приходят при входе/выходе из остановки;
- [ ] «Удвоить» показывает заглушку rewarded (или тихо отказывает — вне платформы).

## Ограничения

- Найденные баги чинить маленькими отдельными коммитами `W2-fix: …`, не смешивать с финальным коммитом документов.
- Новые зависимости и фичи не добавлять (карта, сохранения, подсказки, звуки — недели 3–4).
- `src/sdk/` не трогать; `vite.config.ts` (`base: './'`) не трогать.
- Если белый экран или критичный баг воспроизводится — стоп, собрать симптомы (скрин/текст консоли iframe), вернуться на ревью, не плодить слепые правки.
