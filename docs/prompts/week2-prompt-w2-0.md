## Сквозные ограничения (действуют, из §1 декомпозиции)

1. TypeScript strict: `enum`/`namespace` запрещены (`erasableSyntaxOnly`) — только union-типы и `as const`; импорт типов — `import type { … }` (`verbatimModuleSyntax`); никаких `any`, `as any`, `eslint-disable`.
2. Новые зависимости запрещены. Тест-фреймворков нет — проверка ручная.
3. Логика — чистые функции в `src/game/`, без React и DOM.
4. Строки UI — только `src/strings.ts`; хардкод в JSX запрещён (в этой задаче JSX и не появляется).
5. Ё → Е везде. Слова — существительные, им. падеж, ед. число.
6. SDK — только через `getSdk()`; в эту задачу не лезть.
7. Прогресс — в памяти; localStorage не подключать.
8. Внешних запросов нет; `console.error` допустим только в валидаторе загрузчика (fail fast для кодера).
9. Трогать файлы вне задачи запрещено. Комментарии — по-русски. Перед сдачей `npm run format`.

### 4. Создать `src/game/levels.ts` — загрузчик

```ts
import data from '../data/levels.json'
import type { LevelsFile, StopData } from './types'

// Нормализация строки: верхний регистр + Ё→Е
export function normalizeWord(raw: string): string {
  return raw.trim().toUpperCase().replaceAll('Ё', 'Е')
}
```

Требования к модулю:
- при импорте провалидировать файл «fail fast»: `version` — число; каждая остановка: `id` уникальны, `letters` — ровно 7 символов из `А-Я`, без повторов, `main` — не пустой, все слова 3–7 букв из `А-Я`. Любое нарушение: `console.error` с путём к проблеме (`остановка {id}: …`) и `throw new Error('levels.json не прошёл проверку')` — кодер должен видеть битые данные сразу;
- `letters` из JSON при загрузке нормализовать в массив (`Array.from(...)`) по форме `StopData`;
- экспорт: `getStop(id: number): StopData` (кидает ошибку, если id нет) и `getStopIds(): number[]`.

Библиотеки валидации (zod и т.п.) не тащить — ручные проверки.
