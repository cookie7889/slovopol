1. `src/game/reducer.ts` (создан, 170 строк) — состояние экрана остановки и **чистый** редьюсер (без React, без DOM, без мутаций):

   - ветки `ACCEPT`: длина < 3 → `flash: bad` + `statusShort` (поле **не** чистится — слово можно дописать); `correct`/`bonus` → слово в `guessed`/`guessedMain`/`guessedBonus`, `score += scoreWord(...)`, `current = ''`, `used = []`, `flash: ok|bonus`; `duplicate` → `flash: soft` + `statusDuplicate` (**без тряски**, GDD §3), поле очищается; `invalid` → `flash: bad` + `statusUnknown`, `current = ''`, `used = []`.

## Отклонения от ТЗ / открытые вопросы

1. **Тряска при неверном слове реализована уже в W2-3** (`@keyframes shake` + `data-flash`), хотя раздел «Ограничения» отправляет анимации в W2-4: критерий приёмки W2-3 прямо требует «ЗОНТ → тряска + «Такого слова нет»». Сетка слов, «печатание» найденного слова и попы W2-4 **не** делались; `prefers-reduced-motion` уже учтён.
2. **`GameState` дополнен полем `flashSeq`** (монотонный счётчик) рядом с `flash.seq`: `CLEAR_STATUS` обнуляет вспышку, и без отдельного счётчика `seq` начинался бы заново с 1 — одинаковые события подряд перестали бы различаться (для анимаций W2-4 это критично).
3. **`statusKey` типизирован union-ом `StatusKey`**, а не `string` (в ТЗ — `string | null`): строки статуса в `strings.ts` теперь проверяются компилятором, лишние/опечатанные ключи невозможны.
4. **Дубликат («Уже найдено») очищает поле** — ТЗ молчит про поле в этой ветке. Оставленное слово нельзя принять повторно, поэтому поле освобождается (слово уже найдено, продолжать можно сразу). Короткое слово (статус «Слишком коротко») наоборот **не** очищает поле — его можно дописать.
5. **Прогресс считает только основные слова**: `n = guessedMain.length`, `N = stop.main.length`. Бонусы опциональны, поэтому при их учёте прогресс никогда не достиг бы `N из N` и условие «найдены все основные → остановка пройдена» (W2-5) не сработало бы. Бонусные слова влияют на очки и звёзды, но не на счётчик прогресса.
6. **Меню-заглушка стилизована в `src/styles/base.css`**, а не в отдельном `src/screens/Menu.css`: список файлов задачи не предусматривает файл меню, а правило «один файл на экран» относится к постоянным экранам. С появлением Home-экрана (W3-1) стили меню переедут в собственный файл.
7. **`src/App.css` удалён** как мёртвый код демо-шаблона (в разметке его использование убрано). Файлы `src/assets/*` оставлены по требованию ТЗ.
8. **Остатки шаблона Vite перекрыты в `base.css`**: `src/index.css` (вне скоупа задачи, импортируется в `src/main.tsx`) задаёт `--bg: #fff`, `--accent: #aa3bff`, `#root { width: 1126px }`, тёмную тему `color-scheme: light dark` и `h1 56px`. `base.css` подключается из `src/App.tsx` и попадает в бандл **после** `index.css` (порядок импортов в `main.tsx`), поэтому перекрытия срабатывают — проверено по собранному `dist/assets/index-*.css` (наш `#root{max-width:640px}` идёт вторым правилом).
9. **`Enter` не срабатывает, если фокус на кнопке** — иначе «Принять» вызывалось бы дважды, а «К остановкам» перехватывался бы глобальным обработчиком. Клавиша `Enter` на сфокусированной кнопке вызывает её нативное нажатие.
10. `console.log` в игровом коде не оставлен (только `console.warn` в обработчиках ошибок SDK).
