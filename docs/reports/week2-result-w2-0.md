## Отклонения от ТЗ / открытые вопросы

- **Дополнено сверх списка проверок ТЗ** (инварианты из `types.ts`/ГДД §2, не ослабляют требований ТЗ): `city` — непустая строка; `fact` — строка ≤180 символов; `bonus` — массив; `stops` — непустой массив. Пустой `stops` считаем битыми данными (игра без остановок), падает с fail-fast.
- **Осознанно не проверяется загрузчиком** (дело W2-6, `scripts/validate-dictionary.mjs`): кратность букв слова набору `letters`, дубликаты слов внутри `main`/`bonus`, пересечение `main ∩ bonus`, наличие Ё в исходнике, `fact`/слова в стоп-листе. Загрузчик проверяет форму и целостность, а не семантику словаря.
- `levels.json` после `npm run format` записан с prettier-разбивкой массивов (содержимое данных идентично §4 декомпозиции, отступы/формат — канонические для репозитория).
- `normalizeWord` применяется и к буквам набора, и к словам — в `StopData` попадают уже нормализованные значения (верхний регистр, Ё→Е), поэтому `checkWord` в W2-1 может полагаться на нормализованные данные.
- Файлы вне задачи не трогались: изменения `docs/prompts/week2-prompt-w2-1.md` и `week2-prompt-w2-3.md` в рабочем дереве оставлены оркестратору и в коммит не попали.
